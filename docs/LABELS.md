# Site labels (registry)

Every exterior site gets a short tag (`EXT01` ... `EXT06`). The tag is a **label for people and for scene
object names**; it is not a Firestore id. Ids such as `bike_shed` are what the code, Firestore and the
popup photos use, and they never change (see the note under the table).

| Tag | Name | Scene | Id | Root position x,y,z | Trigger WxHxD | Current visual | Status |
|---|---|---|---|---|---|---|---|
| EXT01 | Main building (building object + POI trigger; renamed in a later task) | Exterior | main_building | building (20,0,13), POI (20,1,-2) | 30x3x8 | building body 67x17.5x18 | blockout built |
| EXT02 | MCA block | Exterior | mca_block | (-41.3,1,23.8) | 51x3x19 | placeholder cube 43x7x11 | placeholder |
| EXT03 | Bike shed | Exterior | bike_shed | (49.7,1,-43.8) | 29x3x16 | barrel-roof shed 21x8, built by EXT03_BikeShed.cs | blockout built |
| EXT04 | Car shed | Exterior | car_shed | (14.4,1,-50.2) | 55x3x23 | lean-to steel canopy 47x6 attached to a classroom block 47x9 (backdrop), built by EXT04_CarShed.cs | blockout built |
| EXT05 | Canteen | Exterior | canteen | (-15.6,1,45.5) | 27x3x19 | placeholder cube 19x4x11 | placeholder |
| EXT06 | Badminton court | Exterior | badminton_court | (66.5,1,27) | 27x3x16 | placeholder cube 19x9x8 | placeholder |

**Do not rename an id** (`bike_shed`, `mca_block`, ...). They are used by `POITriggerVolume.poiId`, the Firestore
`exteriorPOIs` documents and the popup photo file names in `Assets/Resources/RoomPhotos/`. Renaming one silently
breaks the popup and its photo. Only the scene object names carry the `EXTnn_` tags.

## EXT03 bike shed: how it is built

The shed model is generated by a script, not modelled by hand:

- Script: `Assets/Editor/SiteBuilders/EXT03_BikeShed.cs` (all sizes are constants at the top, with comments).
- It finds the shed object in `Exterior.unity` (`POI_BikeShed` the first time, `EXT03_BikeShed` afterwards),
  deletes the old model, and rebuilds the child `EXT03_Model` (groups `Roof`, `Poles`, `Beams`, `Fascia`,
  `Floor`, `Lines`). The root's position, its `POITriggerVolume` and its trigger collider are not touched.
- Materials: `Assets/Materials/Sites/EXT03_*.mat`. Roof mesh: `Assets/Models/Generated/EXT03_RoofVault.asset`.
- `Assets/Scripts/ShedRoofFader.cs` (on `EXT03_Model`) hides the roof, fascia and beams together, because the
  camera looks down from above and behind. They are hidden while the Player is under the shed (footprint + 1 m),
  and also while the line from the Main Camera to the Player passes through them (so the avatar stays visible
  just outside the shed). They come back after 0.3 s of nothing being in the way, so they do not flicker.
- Only the 12 poles have colliders.

### How to resize

1. Change the constants at the top of `Assets/Editor/SiteBuilders/EXT03_BikeShed.cs`
   (for example `Length`, `Depth`, `EaveHeight`, `PolesPerSide`, `BackWall`).
2. Run it again, either:
   - in the Unity Editor: menu **Campus > Build EXT03 BikeShed**, or
   - with Unity closed, from the repo root:
     `Unity -batchmode -quit -projectPath ./UnityProject -executeMethod EXT03_BikeShed.Build -logFile ext03.log`
3. Look at the shed in the Editor, then commit the changed scene and assets.

Running it twice is safe: every run deletes the old model first, so there are never duplicates.
If you change `Length` or `Depth`, also check that the POI trigger on the root (currently 29x3x16) still covers the shed.

## EXT04 car shed: how it is built

The car shed is a lean-to steel canopy (open front facing +z, toward the main building) attached to the front
wall of a single-storey classroom block that stands behind it at -z. It is generated by a script, like EXT03:

- Script: `Assets/Editor/SiteBuilders/EXT04_CarShed.cs` (all sizes are constants at the top, with comments).
  The steps every site builder shares (open the scene, find the site object, make materials, groups and shapes,
  save, tidy the scene file) are in `Assets/Editor/SiteBuilders/SiteBuilderUtil.cs`.
- It finds the object in `Exterior.unity` (`POI_CarShed` the first time, `EXT04_CarShed` afterwards), deletes the
  old model, and rebuilds the child `EXT04_Model` with the groups `Canopy` (`Roof`, `Beams`, `Poles`), `Block`
  (`Walls`, `Plinth`, `Windows`, `Shutters`, `Roof`), `Floor` (`Bands`, `Gravel`, `Path`) and `Cars`. The root's
  position, its `POITriggerVolume` (poiId `car_shed`) and its trigger collider are not touched.
- Materials: `Assets/Materials/Sites/EXT04_*.mat` (no textures).
- `ShedRoofFader` (on `EXT04_Model`) hides only the canopy roof (`Canopy/Roof`) while the Player is under the
  canopy, or the roof is between the camera and the Player. The block's roof, the beams and the poles stay.
- Colliders: every pole, one box for the whole classroom block, and one box per parked car. Roof, floor, gravel,
  path, windows and shutters have none.
- The poles and cars are on physics layer 2 ("Ignore Raycast", the same layer the interior walls use). The avatar still
  collides with them, but the follow camera's single ray ignores them, so a thin pole or a car cannot pull the camera
  against the avatar. The classroom block stays on the Default layer. To change this, edit `CameraPassThroughLayer`.

### How to resize EXT04

Change the constants at the top of `Assets/Editor/SiteBuilders/EXT04_CarShed.cs` (for example `Length`,
`CanopyDepth`, `BlockDepth`, `CarBays`), then run **Campus > Build EXT04 CarShed** in the Unity Editor, or with
Unity closed from the repo root:
`Unity -batchmode -quit -projectPath ./UnityProject -executeMethod EXT04_CarShed.Build -logFile ext04.log`.
Running it twice is safe. If you change `Length`, `CanopyDepth` or `BlockDepth`, also check that the POI trigger on
the root (currently 55x3x23) still covers the shed.
